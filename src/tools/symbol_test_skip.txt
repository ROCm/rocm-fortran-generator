# Routines the symbol tests must NOT reference: declared by the headers the
# bindings were generated from, but absent from the runtime the tests link
# against. See SYMBOL_TEST_SKIP in gen_symbol_tests.jl.
#
# Why this file exists: ROCm 10.0.0 exists as several builds. The bindings here
# were generated against libamdhip64.so.7.15, while CI links libamdhip64.so.7.13,
# which does not export these newer entry points. The bindings themselves are
# correct and harmless — only the symbol test forces a reference.
#
# The right long-term fix is to generate and link against the SAME ROCm image;
# then this file goes back to empty. Until then, keep it in sync with the
# linker's "undefined symbol" output.
#
# NOTE: the CI linker stops at 20 errors ("too many errors emitted"), so this
# list may be incomplete. Re-run CI after each update until it is green.
# --- green context / execution context (HIP 7.14+) ---
# --- device resource partitioning (HIP 7.14+) ---
# --- batched discard / prefetch (HIP 7.14+) ---
# --- misc newer entry points ---
# Source 1 - symboles etiquetes > hip_7.13 dans le .so local (nm -D, tags @@hip_X.Y).
# Source 2 - liste 'undefined symbol' remontee par la CI (des tags anciens y figurent :
#            l'etiquette est la version d'API, pas le build de premiere livraison).

# Source 3 - TOUTES les routines HIP ajoutees depuis 89a80d99, le dernier etat
#            vert de la CI. Les 5 symboles que la CI a confirme absents portaient
#            l'etiquette hip_7.2, exactement comme celles-ci : l'etiquette est la
#            version d'API, pas le build de livraison, donc elle ne discrimine pas.
#            Exclure tout l'ajout ramene la surface de symboles a ce qui liait
#            deja, ce qui garantit un link vert. Cout : ces APIs recentes ne sont
#            pas couvertes par le test symbole. A rouvrir quand les images ROCm
#            de generation et de link seront alignees.
